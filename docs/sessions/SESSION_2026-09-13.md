사용자가 실제 .env가 예전 구성임을 지적했다. 기존 파일에는 VITE_* 항목이 남아 있고
CLOUDFLARE_TUNNEL_TOKEN 등이 없었다. 공개 주소만 반영했던 상태를 수정했다.
- .env.example을 현재 Compose 소비 항목 중심으로 정리하고 실제 .env를 동기화.
- 기존 값/자격증명은 보존, 원본은 Git 제외 backups 폴더에 소유자 전용 권한으로 백업.
- VITE_API_BASE_URL/VITE_AI_API_BASE_URL 제거, 기타 사용자 추가 설정 보존.
- Tunnel 토큰 입력란을 파일 맨 위 공개 주소 섹션에 추가(빈 값).
- 새 .env 권한 0600, 운영 Compose config -q 및 git diff --check 통과.
- DB 비밀번호 변경·컨테이너 재시작·외부 연결은 수행하지 않음.


## 실제 운영 전환 및 Tunnel 연결

사용자가 다시 저장한 .env의 Tunnel 토큰 형식을 비밀값 출력 없이 확인했다.

- 변경 전 portal-db 백업을 추가 생성하고 .env를 권한 0600으로 백업.
- 초기 관리자 해시 미변경·DB 기본 비밀번호를 확인하여 각각 무작위 값으로 교체.
  DB 계정과 .env를 함께 갱신하고 TCP 비밀번호 인증 성공 확인.
  관리자 기존 refresh token을 폐기하고 로그인 정보는 Git 제외 backups/admin-login-* 파일에 0600으로 저장.
- 운영 이미지로 portal-db/api-server/frontend/ai-backend/nginx를 기동.
  portal-db 기존 볼륨·데이터 유지. 확인 시 게시글 0건, ADMIN 1명, USER 2명.
- DB/API/Frontend/AI는 호스트 포트 미공개, Nginx는 127.0.0.1:80만 공개.
  다른 프로젝트 및 기존 ai-bench-db 컨테이너는 변경하지 않음.
- 실제 운영 로컬 HTTP 검증: health 200 UP, 홈/블로그/Office/로그인/글 목록 200,
  가입/익명 글쓰기/댓글/OAuth 401, Actuator/관리자 Office 404.
- 새 관리자 비밀번호 로그인 200, Secure/HttpOnly cookie 확인, 내 글 목록 200, 로그아웃 204.
- cloudflared 기동 및 Cloudflare 연결 4개 등록 확인. 인증 오류 없음.
- 공개 DNS A 레코드 0개, https://gwangwon.dev/health 접속 불가.
  사용자에게 Cloudflare Published application route를 gwangwon.dev → http://nginx:80으로 저장하도록 안내.

## 도메인 HTTPS 공개 확인

사용자가 Cloudflare 공개 경로를 저장했다. 단일 서비스 URL 입력란에는 프로토콜이 필수여서
`nginx:80` 대신 `http://nginx:80` 전체를 입력하도록 안내했다.

- Tunnel에서 gwangwon.dev 및 nginx:80이 포함된 새 설정 수신 확인.
- 실제 https://gwangwon.dev 접속 성공. /health 200 UP, 홈/블로그/Office/로그인/글 목록 200.
- 정적 JS/CSS 샘플 4개 200.
- 방문자 가입·글쓰기·댓글·좋아요·OAuth 요청 401, Actuator/관리자 Office 404.
- 실제 HTTPS 관리자 로그인 200, Secure/HttpOnly cookie 확인, 관리자 내 글 200.
  CookieJar의 HTTPS 쿠키로 refresh 200, 로그아웃 204, 이후 refresh 401 확인.
- 첫 자동 요청은 403이었으며 브라우저 User-Agent를 사용하는 후속 요청은 정상 응답.
  초기 403의 원인은 확정하지 않음. Cloudflare 보안 설정은 변경하지 않았다.
- README 라이브 URL과 컨텍스트/배포 가이드에 실제 공개 상태 반영.
- 미검증: 실제 브라우저 렌더링/모바일 화면(Playwright/Puppeteer 미설치),
  운영 게시글 작성·발행, AI 실제 모델 호출. 대표 게시글과 정기/외부 백업도 후속 운영 작업.

## 공개 화면 품질·채용 포트폴리오 탐색

사용자가 디자인·기능 개선을 요청해 카드·최신 글·메뉴 문제를 먼저 수정하고 동작 테스트 6개를 통과시켰다.

- 임시 /tmp/portfolio-browser-qa에 Playwright를 설치하고 실제 Chromium으로 공개 사이트를 확인. 프로젝트 의존성 변경 없음.
- PC 1440×900 라이트/다크 및 모바일 390×844 라이트: 가로 넘침·pageerror 없음.
