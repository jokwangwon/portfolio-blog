## 후속 구현 — 저장 보호 보완

사용자가 검토 결과에 따라 보완 진행을 승인했다. 이번 범위는 P1 저장 보호 두 건이며 API 요약·고급 콘텐츠·구 명세 통합은 후속이다.

- blog-ui-design에 원복/복원 대기 구분, 메뉴 이동 실패 확인, 탭 내 보조 보관과 한계를 먼저 명시했다.
- 기존 코드에서 새 회귀 테스트 3개 실패 확인 후 구현. 편집기 밖 새로고침 경고도 별도 실패 테스트 후 보완했다.
- useAutoSave의 enabled(복원 선택 완료)와 dirty(서버 기준 변경)를 분리했다. 원복 시 중간 복구본 정리, 저장 실패 시 오래된 보관 시각 제거.

- 저장소 실패 때 메모리 보조 복구본을 두어 SPA 이동·재진입 시 마지막 입력을 복원한다. 메모리만 남은 동안 편집기 밖에서도 beforeunload 확인 유지. 서버 저장/폐기/원복 시 정리한다.

## 후속 요구 — 지식 저장소와 회사 경험

- 공부·독서·개발/업무 기록을 대량 보관하고 Obsidian과 같은 관계 그래프를 희망했다.
- 공개 범위 질문에 ‘기본 공개, 선택한 글 비공개’로 확정했다. 작성 초안을 자동 발행하지 않고 발행 시 공개 범위 기본값으로 해석했다.
- 현재 재직 중이라고 표현하지 않도록 정정. 기원테크·트러스트랩의 전체 기록을 포트폴리오에 포함하도록 요구했다.
- 현행 Post/Category/검색/경력 데이터 및 과거 Git 코드를 비교했다. 현재 포트폴리오에는 두 회사 기록이 없고 과거 기원테크 문구는 기간/역할 근거가 부족하다. 트러스트랩 상세는 저장소에서 찾지 못했다.
- [지식 저장소 확장 초안](../architecture/knowledge-workspace-design.md)과 [자료 전달 양식](../content/career-records-intake.md)을 작성했다. Obsidian 공식 링크/그래프 안내를 참고했다.
- 다른 GPT/Claude의 정리본을 전달하거나 사용자가 직접 정보를 줄 수 있다. 기존 대화를 자동 조회했다고 주장하지 않았으며 근거/미확인 항목을 구분하도록 요청했다.
- 기존 blog/portfolio 설계와 오래된 아키텍처의 현재 재직 문구를 정정했다. 데이터 구조/API/화면 구현·운영 배포는 하지 않았다. 경력 자료는 아직 미수신이다.
