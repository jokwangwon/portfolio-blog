# 블로그 화면과 읽기 흐름 검토 — 2026-09-13

현재 블로그는 공개 글이 없어 빈 목록을 보여준다. 빈 상태만으로 본문과 카드의 품질을 판단할 수 없어서 실제 공개 빈 목록과 브라우저에서만 주입한 검토용 목록·본문·HTTP 500 응답을 구분해 확인했다. 실제 DB에 글을 만들거나 발행하지 않았다.

## 확인 범위

- 실제 공개 사이트의 1440px PC, 390px·320px 모바일, 라이트 모드.
- 각 폭에서 빈 목록·예시 목록·예시 상세·오류 목록: 12개 조합.
- 예시 본문은 제목·문단·SQL·표를 포함하며, 실제 개발 성과를 뜻하지 않는다.
- 블로그 다크 모드·관리자 글쓰기·실제 검색 데이터의 정확도·검색엔진 노출은 이번 검토 범위에 포함하지 않았다.
- 기존 개발용 테마 패널은 이번 홈 개선과 함께 운영 환경에서 비노출 처리했다. 아래 블로그 캡처는 그 직전 공개본이다.

## 우선순위와 근거

| 우선순위 | 확인한 문제 | 개선 방향 |
|---|---|---|
| 1 | MarkdownRenderer가 prose 클래스를 사용하지만 typography 플러그인과 대응 스타일이 없다. 실제 h2와 p가 같은 16px·보통 굵기, 문단 여백 0으로 표시됨 | 제목 크기·간격, 문단 행간·여백, 목록·인용·코드·표 스타일을 명시적으로 정의. 긴 글 읽기부터 복구 |
| 1 | 긴 태그 3개를 가진 예시에서 목록 폭 410px·상세 폭 452px. 390px와 320px 화면 밖으로 넘침 | 카드 작성자/태그와 상세 메타데이터 줄바꿈, 긴 문자열 처리, 코드·표 내부 스크롤을 점검 |
| 1 | 목록 API가 500이면 목록이 비지만 오류 문구와 재시도 없음 | 로딩·전체 빈 상태·검색 결과 없음·오류를 별도로 표시하고 재시도 제공 |
| 2 | 비어 있는 목록에서 카테고리·검색·관리자 로그인이 주요 화면을 차지함 | 짧은 블로그 소개와 실제 글 중심으로 구성. 빈 상태에는 프로젝트로 돌아갈 명확한 링크 제공 |
| 2 | 공개 읽기 전용인데 PostCard에 좋아요 0이 표시됨 | 좋아요 표시 제거. 제목·요약·주제·발행일을 우선하고 조회수는 비중 축소 |
| 2 | 검색/분류/페이지가 컴포넌트 내부 상태라 URL 공유·새로고침 복원이 어려움 | 검색어·분류·페이지를 URL과 동기화. 검색 범위와 현재 필터를 명시 |
| 2 | 목록 기본 정렬은 createdAt, 최근 글 예정 기능은 publishedAt 기준 | 방문자 목록은 발행일 기준으로 통일. 초안을 오래 보관했다 발행한 글의 순서 검증 |
| 3 | 본문 목차/제목 앵커가 없고 내부 링크도 새 탭으로 열림 | 긴 글에만 목차 제공, 제목 링크·코드 복사, 내부/외부 링크 동작 구분 |
| 3 | 홈 최신 글은 아직 고정 빈 상태. 프로젝트와 관련 기록을 이어 읽기 어려움 | 실제 공개 글이 있을 때 최신 글 표시, 관련 프로젝트 저장소·문제 해결 글 연결 |

검색 입력의 명시적인 레이블과 카테고리 선택 상태도 보완할 필요가 있다. 상세 화면은 네트워크 오류와 글 없음에 동일한 안내를 표시하므로 오류를 구분해야 한다.

## 권장 구성

블로그 목록은 짧은 주제 소개 → 검색·분류 → 발행일 순 글 목록으로 구성한다. 현재 글 수에서는 큰 사이드바보다 가벼운 필터가 적합하다. 글 수가 늘기 전에는 빈 카테고리를 다수 추가하지 않는다.

글 상세는 제목 → 한 문단 요약 → 주제·발행일 → 본문 → 관련 프로젝트/기록 순서로 구성한다. 본문은 PC 약 680~760px 폭, 모바일 안쪽 여백을 유지하고 코드·표만 내부에서 가로 스크롤되도록 검증한다.

콘텐츠 비중은 우선 프로젝트 문제 해결 기록을 중심으로 검토했다. 사용자 선호에 따라 Oracle 학습 기록과의 비중을 조정할 수 있다. 추천 글 구조는 다음과 같다.

1. 어떤 상황에서 무엇을 확인하려 했는가.
2. 원인 후보와 직접 확인한 근거는 무엇인가.
3. 어떤 선택을 했고 왜 선택했는가.
4. 결과를 어떻게 확인했으며 남은 한계는 무엇인가.
5. 관련 코드·커밋·문서 링크는 어디인가.

후보 주제는 이 포트폴리오의 조회 전용 공개 과정, DB 백업·복원 검증, Oracle 로그 파싱 중 확인한 문제다. 실제 담당 범위·결과를 확인한 뒤 작성해야 하며 위 주제를 이미 발행한 글처럼 표시하지 않는다.

## 단계별 진행안

1. 본문 타이포그래피 복구 + 모바일 카드/태그/메타데이터 넘침 수정.
2. 목록의 오류·빈 상태·검색 결과 안내, 공개 좋아요 표시 정리.
3. 목록·검색 상태 URL 동기화, 발행일 정렬, 최근 글 연결.
4. 실제 글 1~2편을 기준으로 목차·코드·프로젝트 연결을 다듬기.

이번에는 방향을 검토했으며 블로그 본문·목록 기능 변경은 아직 배포하지 않았다.
