# 글 작성 사용성 개선 — 2026-09-13

사용자가 글 작성 사용성 개선을 요청해 제목 입력부터 본문 편집·복구·서버 임시저장·발행까지 점검했다.

## 확인한 문제와 수정

| 기존 문제 | 이번 변경 |
|---|---|
| 서버 응답 전에 복구본 삭제, 저장 실패 안내 없음 | 제출 직전 보관 → 성공 응답 확인 후 삭제. 실패하면 입력과 복구본 유지·재시도 안내 |
| 복원 배너가 떠 있는 동안 자동 저장이 기존 복구본을 덮을 수 있음 | 복원/버리기 결정 전 편집·자동 저장 중지 |
| 30초 간격 보관, 24시간 뒤 복구본 삭제 | 변경 후 1.5초 지연 보관, 페이지 숨김/이탈 직전 보관. 시간 경과에 따른 자동 삭제 제거 |
| 브라우저 저장 실패를 무시하고 저장 시각 표시 | 브라우저 보관 실패 안내. 서버 임시저장과 브라우저 복구본을 명확히 구분 |
| 상태 선택 후 ‘저장’ 버튼이라 발행 여부가 불명확 | ‘임시저장’과 ‘발행하기’를 구분. 발행된 글은 ‘변경 사항 저장’만 제공 |
| 새 임시저장 후 상세 페이지로 이동 | 생성한 초안의 수정 화면으로 이동해 이어쓰기 |
| 요약·분류·관리 기능이 본문보다 먼저 나옴 | 제목 → 본문 → 펼칠 수 있는 요약·분류·태그, 삭제 기능은 관리 영역으로 이동 |
| 본문 도구가 선택/슬래시 메뉴에 의존 | 제목·굵게·목록·코드·되돌리기 버튼 상시 제공, Ctrl/Cmd+S 저장 |
| 작성 화면에 공개 렌더러 미리보기 없음 | 편집·마크다운·미리보기 제공. 공개 본문의 제목·문단·목록 스타일도 함께 복구 |
| 관리자 메뉴의 모바일 폭 문제 | 관리자 헤더 줄바꿈. 모바일 저장 바는 본문을 가리지 않도록 일반 흐름에 배치 |

복구본 버리기에는 명시적인 확인을 둔다. 서버 제출 중에는 입력과 중복 제출을 잠그며, 서버 저장 후 새로 편집하면 미저장 상태로 다시 표시한다.

## 검증

- 저장·복원 결함 재현 테스트 10개가 기존 구현에서 실패하는 것을 확인한 후 수정했다.
- 프런트엔드 전체 145 tests 통과. 이후 저장 완료 상태의 재편집 표시 테스트를 추가하고 저장 관련 15 tests 재검증.
- 운영 Docker 빌드·TypeScript 통과. lint 오류 0, 기존 경고 6.
- Chromium PC 1440px 라이트/다크, 모바일 390px/320px에서 입력 → 마크다운 → 미리보기 → 편집 복귀 → 새로고침/복원 → 서버 오류 → Ctrl+S 임시저장 → 초안 수정 → 발행 흐름을 검증했다.
- 저장 요청은 브라우저에서만 가로채는 모의 응답이다. 실제 DB에 글을 만들거나 발행하지 않았다.
- 미리보기와 공개 본문의 h2가 모두 24px. 검사한 작성 화면에서 가로 넘침·pageerror 없음.

## 남은 범위

- 로컬 복구본은 같은 브라우저의 보조 수단이며, 다른 기기에서 이어 쓰려면 서버 임시저장이 필요하다.
- 동시 탭 편집 충돌 병합, 이미지 업로드와 붙여넣기 이미지의 공개 표시, 고급 블록(색상·임베드 등)의 왕복 보존은 별도 검증·개선 대상이다.
- 기존 이미지 붙여넣기는 data URL을 만들지만 공개 렌더러는 이를 허용하지 않는다. 이번에는 업로드 API나 보안 허용 범위를 임의로 확장하지 않았다.
- AI 요약·분류 관리 실패 안내는 추가했으나 실제 AI 모델 호출과 운영 카테고리·태그 생성/삭제는 실행하지 않았다.
- 블로그 목록 오류·검색·긴 태그 넘침과 홈 최근 글 기능은 후속 범위다.


## 공개 반영 확인

최종 이미지를 frontend에 반영하고 Nginx를 reload했다. 공개 HTTPS에서 위 PC·모바일·다크 네 조합의 작성 흐름을 모의 서버 응답으로 다시 검증했다.
실제 관리자 로그인 후 새 글 화면 접근, 미리보기·임시저장 버튼을 확인하고 로그아웃 204를 확인했다. 실제 글 입력·생성·발행 없음. health 200·UP.
