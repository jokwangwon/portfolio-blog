# 블로그 공개 범위 분리 — 구현·배포 기록

2026-09-15 · 운영 반영 완료

## 바뀐 동작

- 글 작성 상태(DRAFT/PUBLISHED/ARCHIVED)와 공개 범위(PUBLIC/PRIVATE)를 분리했다. 새 글은 기본 공개이며, 비공개를 선택해 완성된 글도 본인만 읽는 기록으로 저장할 수 있다.
- 편집기의 공개 범위 선택은 서버 저장 성공 때 적용된다. Ctrl+S·실패 후 재시도·브라우저 복구본에도 선택을 보존하며, 이전 형식 복구본에 공개 범위가 없으면 현재 서버 설정을 유지한다.
- `/blog/drafts`를 ‘내 기록’으로 확장했다. 본인 기록 전체를 최근 수정 순으로 조회하고 작성 상태·공개 범위를 독립적으로 필터링한다. 필터 변경 중에도 조작부를 유지한다.
- 공개 목록·검색·카테고리·태그·slug 조회는 PUBLISHED + PUBLIC만 반환한다. ID 상세는 공개 글 또는 작성자만 조회할 수 있고 그 외는 404다. 비공개 조회는 조회 수를 늘리지 않는다.
- 댓글·좋아요 서비스도 부모 글의 공개 여부를 검사한다. 운영의 댓글·좋아요 기능 전체 차단 정책은 유지한다.
- 글 응답은 `Cache-Control: no-store`, 인증 사용자별 상세/내 기록 캐시, 로그아웃 시 진행 요청 취소·캐시 제거를 적용했다.

## 호환성과 검증

- Flyway V2로 기존 행의 visibility를 PUBLIC으로 채운다. 원래 status는 그대로이므로 기존 초안·보관 글은 계속 방문자에게 숨겨진다. 생성 요청에서 생략하면 PUBLIC, 수정 요청에서 생략하면 기존 공개 범위를 유지한다. 잘못된 값은 400이다.
- 백엔드 `./gradlew check`: 151 tests, 실패 0. 별도 PostgreSQL에서 실제 V1 → V2를 적용해 본문·상태 보존 및 제약 조건을 검증했다.
- 프런트엔드 37개 파일 202 tests 통과. 테스트 파일 형식 정리 후 해당 32 tests도 통과했다. lint 오류 0이며 기존 경고가 남는다.
- 운영 이미지 빌드와 애플리케이션 TypeScript 검사 통과. 작업 디렉터리의 별도 `tsc --noEmit`은 기존 테스트 fixture 타입과 오래된 `.next/dev`의 `[slug]` 생성 타입 문제로 실패한다. 이번 운영 빌드의 검사와 구분한다.
- 격리된 운영 이미지·DB로 1280px 라이트/390px 다크에서 실제 관리자 로그인, 기본 공개 글 생성, 저장 전 공개 유지, 비공개 저장, 공개 검색 제외, 댓글 차단, 내 기록 필터, 로그아웃 후 뒤로 가기·직접 URL 차단을 검증했다. 가로 넘침·JS 오류 없음. [결과](assets/2026-09-15/blog-visibility/results.json).
- 실제 HTTPS: health·글 목록·카테고리·작업실 200, 익명 내 기록/글 작성 401, 공개 글 0건 유지, 홈·기록·작업실 모바일 넘침·JS 오류 없음. [결과](assets/2026-09-15/blog-visibility/public-results.json).
