# 글 저장 충돌 방지 구현 범위

2026-09-15 사용자 승인. 기존 knowledge-storage-ai-design 1단계의 구현이며 이력·AI 작업은 후속이다.

- V4: edit_version BIGINT 기본0, edited_at nullable, content_format MARKDOWN_V1. 기존 본문/ID/공개 범위 유지. 기존 편집 시각은 추측하지 않는다.
- PUT expectedEditVersion 필수(0 이상 정수). DB 행 잠금 후 권한 검사·버전 비교. 불일치409 POST_EDIT_CONFLICT, 누락400 POST_EDIT_VERSION_REQUIRED. 같은 내용 저장은 버전/editedAt 증가 없이 응답. 실제 글·분류·상태·공개 범위 변경 때만 증가한다.
- 조회수·좋아요는 해당 카운터만 갱신하고 editVersion/editedAt/updatedAt을 변경하지 않는다. 본인 목록은 본문 제외 응답으로 전환한다.
- 편집기는 처음 읽은 버전을 보존한다. 백그라운드 재조회가 작성 중 기준 버전을 올리지 않는다. 성공 시 응답 버전으로 갱신한다. 브라우저 복구본에도 expectedEditVersion을 저장한다.
- 409/버전 없는 구형 복구본은 입력을 유지하고 최신 글 비교를 제공한다. 사용자가 비교한 버전 기준으로 편집을 계속하겠다고 선택할 때만 버전을 갱신한다. 선택 자체는 저장/공개하지 않는다. 그 사이 변경이 더 있으면 재차409.
- 배포는 V4/API 먼저(일시 호환 옵션으로 구형 요청 수용), 새 frontend, API 버전 필수 옵션 확정 순서다. 최종 운영과 기본값은 필수이며 누락 요청 차단 검증 전 완료로 보고하지 않는다.
- 테스트: 동시 저장 하나만 성공, no-op, 공개 범위/분류 변경, 조회·좋아요와 동시 수정, 권한 우선 검사, 기존 V3 migration 데이터, 복구본과 입력 보존·명시적 비교/버전 전환, 연속 임시저장, 두 브라우저 실제409.
